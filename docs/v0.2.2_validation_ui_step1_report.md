# v0.2.2 Validation Step 2.1 UI 接入报告

## 1. 本次目标

本次把 Mock Validation 接入现有 Streamlit OCR/确认页面，用于验证独立 Validation 状态和结果展示。

本次没有接入真实 Doubao Validation，没有修改 Extraction Prompt、ExperimentResult、Excel、README 或现有 Extraction Provider。

## 2. 修改文件

### `pages/2_OCR.py`

- 在 Extraction 结果表格后增加“AI 数据检查”区域；
- 每次 Extraction 重新成功后清除该结果对应的旧 Validation 状态；
- 开发模式的 Mock Extraction 也显示同一 Validation 入口，便于无费用页面测试；
- 不改变原 Extraction 调用和返回结果；
- 不改变原确认和 Excel 代码。

## 3. 新增文件

### `utils/__init__.py`

建立页面辅助模块目录。

### `utils/validation_ui.py`

提供：

- 独立 Validation Session State 键；
- 未运行、运行中、成功和失败状态；
- `run_mock_validation()`；
- `clear_validation_state()`；
- Streamlit Mock Validation 展示；
- warnings、suggestions、uncertain_items 的中文分区；
- finding 的中文问题类型和置信度显示。

### `tests/test_validation_ui_state.py`

验证：

- 首次状态为未运行；
- Mock Validation 成功后切换为成功；
- ValidationResult 与 Extraction 结果分开保存；
- Validation 失败后切换为失败状态；
- 失败信息可读取；
- 失败不会修改或删除 Extraction 结果；
- 清理 Validation 状态不会清理 Extraction 结果。

## 4. 页面流程

```text
Extraction 成功
  ↓
显示结构化结果
  ↓
AI 数据检查：尚未运行
  ↓
用户点击“运行 AI 数据检查”
  ↓
MockValidationProvider
  ↓
ValidationResult 独立保存
  ↓
显示警告 / AI 建议 / 不确定项
```

当前页面明确提示：

- 使用的是 Mock 模拟检查；
- 不调用真实 AI；
- 不产生费用；
- 不修改 Extraction 原始数据。

## 5. 状态设计

每个结果使用独立 Session State：

```text
validation_status_{result_id}
validation_result_{result_id}
validation_error_{result_id}
```

支持：

- `not_run`：未运行；
- `running`：运行中；
- `succeeded`：运行成功；
- `failed`：运行失败。

Extraction 结果仍保存在原 `doubao_result_*` 或开发 Mock key 中，Validation 不会覆盖它。
