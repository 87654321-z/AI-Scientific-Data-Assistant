# v0.2.2 Validation Step 1 MVP 实现方案

## 1. MVP 目标

Validation Step 1 只验证一条最小链路：

```text
ExperimentResult（Extraction 结果）
        ↓
生成只读、精简的校验输入
        ↓
ValidationProvider
        ↓
严格 JSON
        ↓
ValidationResult
```

本阶段只检查已经提取出的结构化数据，不修改 Extraction 结果，不接入确认页面，不改变 Excel，也不实现图片二次视觉复核。

### 1.1 MVP 必须完成

- 接收现有 `ExperimentResult`；
- 检查缺失值、字段类型、编号格式、重复信息和明显可疑值；
- 返回结构化 `warnings`、`suggestions` 和 `uncertain_items`；
- 每个可操作项目包含稳定的行号和字段名；
- 保留观察值，AI 只提供建议；
- API、超时或 JSON 失败时，不影响原 Extraction 结果；
- 支持 Mock 测试，不要求每次测试都产生真实 API 费用。

### 1.2 MVP 不实现

- 不修改人工确认页面；
- 不把 AI 建议写入最终值；
- 不修改 Excel 工作表；
- 不重新查看原始图片；
- 不检查 Extraction 是否漏掉图片中的整行；
- 不计算平均值、标准差、显著性或自动异常阈值；
- 不实现分块 Validation、多模型比较或自动路由；
- 不修改 `VisionProvider.process_images()`。

## 2. 建议新增文件

### 2.1 必需文件

```text
core/
    validation_schemas.py
    validation_service.py

prompts/
    validation_prompt.py

providers/
    base_validation_provider.py
    mock_validation_provider.py
    doubao_validation_provider.py
    validation_provider_factory.py

tests/
    test_validation_prompt.py
    test_validation_service.py
    test_doubao_validation_provider.py
```

### 2.2 文件职责

#### `core/validation_schemas.py`

只定义 Validation 自己的数据类型：

- `ValidationFinding`
- `ValidationResult`
- 可选的受控常量，例如问题类型和处理状态

它不导入 Streamlit，也不包含 API 调用。

#### `core/validation_service.py`

提供平台无关主函数：

```python
validate_experiment_result(
    experiment_result,
    provider_name,
    experiment_context=None,
) -> ValidationResult
```

职责：

1. 从 `ExperimentResult` 构建只读校验快照；
2. 创建 Validation Provider；
3. 调用 Provider；
4. 返回独立 `ValidationResult`；
5. 确认调用前后的 Extraction 数据未被修改。

#### `prompts/validation_prompt.py`

构造数据校验 Prompt。输入是精简 JSON，不是图片，也不是完整 Python 对象。

#### `providers/base_validation_provider.py`

定义与视觉提取分开的抽象接口。

#### `providers/mock_validation_provider.py`

返回固定 ValidationResult，用于无网络测试和后续页面开发。

#### `providers/doubao_validation_provider.py`

使用当前统一 AI 配置调用豆包兼容接口，只处理“结构化数据 → ValidationResult”。

#### `providers/validation_provider_factory.py`

根据名称创建 Mock 或 Doubao Validation Provider，避免 `core/` 直接依赖某个模型。

#### `tests/`

覆盖 Prompt、数据只读性、JSON 解析、异常隔离和 Provider 配置，不包含真实 API Key。

### 2.3 本阶段不新增的文件

- 不新增页面；
- 不新增 Excel 模块；
- 不新增数据库；
- 不新增图片裁剪或 OCR 模块；
- 不修改现有 `scientific_data_validation_prompt.py`，它继续作为 legacy 流程文件保留。

## 3. 是否修改 `ExperimentResult`

### 3.1 Step 1 决策：不修改

Validation Step 1 不需要修改 `ExperimentResult`。

建议让：

```python
validation_result = validate_experiment_result(experiment_result, "mock")
```

返回一个独立对象，而不是把结果直接写回 `experiment_result`。

理由：

1. 本阶段尚未接入 UI 和 Excel，没有必要提前改变核心数据模型；
2. 独立返回值最容易验证 Validation 没有修改 Extraction；
3. 不会影响现有 Mock、legacy、预处理、人工确认和 Excel 流程；
4. 如果 Validation 失败，调用方仍持有原来的 `ExperimentResult`；
5. 避免在尚未验证字段是否合理前固化数据模型。

### 3.2 Step 2 的可能变化

人工确认页面接入后，可以再评估给 `ExperimentResult` 增加可选字段：

```python
validation_result: ValidationResult | None = None
```

该字段应有默认值 `None`，保证旧对象兼容。但这不属于 Step 1。

### 3.3 不使用现有 `UncertainItem` 作为主结构

现有 `UncertainItem(location, content, reason)` 缺少稳定行列定位和建议字段。MVP 不应继续把结构化信息塞进 `content` 字符串，再让页面解析自然语言。

Validation 应先使用独立结构：

```python
@dataclass
class ValidationFinding:
    finding_id: str
    scope: str
    row_index: int | None
    column_name: str | None
    observed_value: Any
    issue_type: str
    reason: str
    suggested_value: Any = None
    confidence: str = "low"
```

```python
@dataclass
class ValidationResult:
    warnings: list[str]
    suggestions: list[ValidationFinding]
    uncertain_items: list[ValidationFinding]
    provider: str
    status: str
    response_metadata: dict[str, Any] = field(default_factory=dict)
```

`ValidationFinding` 不包含 `final_value`，因为 Step 1 不执行用户确认。

## 4. Validation 输入快照

### 4.1 快照来源

每行优先读取：

```text
DataRow.observed_values
```

只有旧对象的 `observed_values` 为空时，才回退读取：

```text
DataRow.values
```

这样可以避免把用户已修改值错误地当作原始观察值。

### 4.2 最小输入格式

```json
{
  "columns": [
    {
      "internal_name": "treatment_id",
      "display_name": "处理编号",
      "original_unit": null
    },
    {
      "internal_name": "measurement",
      "display_name": "测量值",
      "original_unit": "mg"
    }
  ],
  "observed_rows": [
    {
      "row_index": 1,
      "values": {
        "treatment_id": "S0/L/E+/N1",
        "measurement": "4.58"
      },
      "replicate_group": "S0/L/E+/N1",
      "replicate_index": 1
    }
  ],
  "experiment_context": null
}
```

### 4.3 明确排除

不向 Validation 模型发送：

- `raw_text`；
- `model_response_logs`；
- 图片 Base64；
- 旧 AI 建议；
- 用户最终值；
- Excel 内容；
- API Key；
- 长篇修改记录。

这可以减少 token、避免阶段信息混淆，并降低长 JSON 风险。

## 5. Validation Prompt 设计

### 5.1 Prompt 职责

Prompt 只检查输入数据，不重新输出完整数据表。

建议结构：

1. 角色与任务；
2. 绝对只读规则；
3. MVP 检查项目；
4. 建议生成规则；
5. 严格 JSON 格式；
6. 禁止输出内容。

### 5.2 绝对规则

Prompt 必须明确：

- 输入中的 `observed_value` 是只读事实记录；
- 不得返回修改后的 `observed_rows`；
- 不得删除、合并、补写或排序数据行；
- 缺失测量值不得根据规律推算；
- 可以给建议，但建议必须与原始值分离；
- 无法定位到具体行列时只生成 warning；
- 不输出分析过程、Markdown 或完整输入副本。

### 5.3 MVP 检查范围

只检查：

- 关键字段为空；
- 同列数据类型明显不一致；
- 处理/样品编号分段形式明显异常；
- 重复组相同但 `replicate_index` 缺失、重复或不连续；
- 单位在字段层缺失或冲突；
- 数值中出现明显非数值字符；
- 数据中存在需要人工检查的模糊字符；
- 在同一列上下文中明显可疑的值。

“可疑极端值”只能提示，不允许宣布该数据错误。Step 1 不要求模型做统计检验。

### 5.4 建议生成规则

- 有合理候选时放入 `suggestions`；
- 没有合理候选但需要检查时放入 `uncertain_items`；
- `confidence` 不能决定是否自动修改，因为 MVP 不自动修改；
- `suggested_value` 不得覆盖或替代 `observed_value`；
- 不允许为缺失的实验测量值编造建议数值；
- 对编号中明显多出的字符，可以提出低置信度候选；
- 每个位置单独输出，不能把多行问题合并。

### 5.5 严格输出格式

```json
{
  "warnings": [
    "编号序列可能存在间断，请人工检查。"
  ],
  "suggestions": [
    {
      "finding_id": "validation-0001",
      "scope": "cell",
      "row_index": 2,
      "column_name": "treatment_id",
      "observed_value": "S0/AH/E+/N3",
      "issue_type": "identifier_pattern",
      "reason": "第二分段与同列其余 L/H 取值不一致。",
      "suggested_value": "S0/H/E+/N3",
      "confidence": "low"
    }
  ],
  "uncertain_items": [
    {
      "finding_id": "validation-0002",
      "scope": "cell",
      "row_index": 3,
      "column_name": "measurement",
      "observed_value": "0.0?",
      "issue_type": "unresolved_character",
      "reason": "数值包含无法确认的字符。",
      "suggested_value": null,
      "confidence": "low"
    }
  ]
}
```

### 5.6 输出长度控制

- 不返回 `columns` 和 `observed_rows`；
- 不返回输入副本；
- `reason` 限制为一句简短中文；
- 没有发现时返回空列表；
- 不输出 reasoning、basis 长文或解释段落；
- 不重复生成 warning 和 finding；
- Step 1 暂不实现分块，测试时应设置合理最大行数并记录限制。

## 6. ValidationProvider 设计

### 6.1 独立接口

建议接口：

```python
class ValidationProvider(ABC):
    name: str

    @abstractmethod
    def validate_result(
        self,
        experiment_result: ExperimentResult,
        experiment_context: str | None = None,
    ) -> ValidationResult:
        ...
```

不修改：

```python
VisionProvider.process_images(...)
```

原因是 Extraction 输入是图片，而 Validation 输入是结构化结果，两者职责不同。

### 6.2 MockValidationProvider

Mock 应返回固定结果，例如：

- 第 2 行处理编号建议；
- 第 3 行数值模糊项；
- 一条字段单位 warning。

Mock 不读取网络、不需要 API Key，并应保证不会修改传入对象。

### 6.3 DoubaoValidationProvider

职责：

1. 通过现有统一配置读取 API Key、Model 和 Base URL；
2. 构造 Validation Prompt；
3. 发送纯文本请求；
4. 解析严格 JSON；
5. 转换为 `ValidationResult`；
6. 记录不含密钥的响应诊断。

稳定性策略与 v0.2.1 Provider 保持一致：

- 单次请求 180 秒 timeout；
- SDK 隐式重试关闭；
- JSON 失败最多显式重试一次；
- 区分网络错误、API 错误、超时、输出截断和 JSON 解析错误；
- 记录 response id、finish reason、token usage、输出长度和耗时；
- 不打印 API Key 或完整配置。

### 6.4 Provider Factory

建议：

```python
create_validation_provider("mock")
create_validation_provider("doubao")
```

不要让 `validation_service.py` 直接导入并实例化 Doubao Provider。

### 6.5 不建议的方案

MVP 不建议：

- 给 `VisionProvider.process_images()` 增加 `stage="validation"`；
- 把 ExperimentResult JSON 塞进 `experiment_context`；
- 让 Validation Provider 返回新的 ExperimentResult；
- 直接调用当前 legacy `_add_validation_findings()`；
- 为了复用私有方法而大规模重构 DoubaoProvider。

## 7. Validation Service 设计

建议主函数：

```python
def validate_experiment_result(
    experiment_result: ExperimentResult,
    provider_name: str,
    experiment_context: str | None = None,
) -> ValidationResult:
    ...
```

执行顺序：

1. 校验输入对象存在 `columns` 和 `rows`；
2. 生成深拷贝或不可变的校验快照；
3. 保存调用前的观察数据摘要，用于测试只读性；
4. 通过 factory 创建 Validation Provider；
5. 调用 `validate_result()`；
6. 校验所有 finding 的行号和字段名；
7. 无法定位的 finding 降级为 warning，不修改原数据；
8. 返回 ValidationResult。

Step 1 不把返回值附加到 ExperimentResult。

## 8. 最小测试案例

### 8.1 Prompt 结构测试

输入一个两行 ExperimentResult，检查生成 Prompt：

- 包含字段和观察行；
- 不包含 `raw_text`；
- 不包含 API Key；
- 不要求返回完整 `observed_rows`；
- 明确禁止修改原始值；
- JSON 字段名与 parser 一致。

### 8.2 正常数据

输入：

```text
1  S0/L/E+/N1  4.58
2  S0/L/E+/N2  4.51
```

Mock 输出：

```json
{"warnings": [], "suggestions": [], "uncertain_items": []}
```

预期：

- ValidationResult 状态为成功；
- 原 ExperimentResult 完全不变。

### 8.3 可建议的编号异常

输入：

```text
1  S0/L/E+/N1
2  S0/AH/E+/N2
3  S0/H/E+/N3
```

预期 finding：

- `row_index=2`
- `column_name=treatment_id`
- `observed_value=S0/AH/E+/N2`
- `suggested_value=S0/H/E+/N2`
- `issue_type=identifier_pattern`
- `confidence=low`

检查建议没有进入 `rows` 或 `final_value`。

### 8.4 无法推断的模糊数值

输入：

```text
measurement = 0.0?
```

预期：

- 进入 `uncertain_items`；
- `suggested_value=null`；
- 不生成虚构测量值。

### 8.5 单字段缺失与整行缺失

案例 A：处理编号存在，测量值为空。

预期：提示 `missing_value`，保留整行。

案例 B：整行所有字段为空。

预期：只提示人工检查；Validation 不删除该行。

### 8.6 重复信息不一致

输入同一 `replicate_group`：

```text
replicate_index = 1, 2, 2
```

预期：生成重复序号冲突提示，不合并或改写任何行。

### 8.7 定位字段无效

Mock 返回不存在的 `row_index=99` 或未知 `column_name`。

预期：

- 不抛出导致流程崩溃的异常；
- 该项降级为 warning；
- 其他有效 finding 正常保留。

### 8.8 JSON 解析失败

模拟：

- Markdown 包裹 JSON；
- 未闭合 JSON；
- `finish_reason=length`。

预期：

- 按约定最多重试一次；
- 第二次仍失败则返回明确分类错误；
- ExperimentResult 不变。

### 8.9 timeout

模拟 `APITimeoutError`。

预期：

- 中文提示“AI 数据检查请求超时”；
- 不泄露 API Key；
- Extraction 结果仍可使用。

### 8.10 Extraction 回归测试

检查：

- `DoubaoProvider.process_images()` 默认仍是 Extraction；
- `stage="legacy"` 仍可使用；
- 不调用 Validation 时不会产生额外 API 请求；
- 原网页、人工确认和 Excel 函数不需要改变；
- 原有 Extraction 编译和 Mock 测试通过。

## 9. 不影响现有 Extraction 的保证

### 9.1 代码隔离

Step 1 只新增独立模块，不修改以下路径：

- `prompts/extraction_prompt.py`
- `providers/base_vision_provider.py`
- `core/experiment_parser.py`
- `pages/2_OCR.py`
- `core/review_service.py`
- `core/excel_exporter.py`

### 9.2 调用隔离

现有默认流程保持：

```text
process_experiment_images()
  → VisionProvider
  → Extraction
  → ExperimentResult
```

只有测试或未来明确入口主动调用：

```text
validate_experiment_result()
```

才会产生第二次 API 请求。

### 9.3 数据隔离

- Validation 输入使用只读快照；
- ValidationResult 独立返回；
- 不修改 `rows`、`observed_values`、`columns` 或 `user_confirmed`；
- 不写 `ai_suggested_rows`；
- 不写 Excel；
- 测试比较调用前后对象，验证没有副作用。

### 9.4 失败隔离

Validation API、JSON 或 timeout 错误不会被包装成 Extraction 失败。调用方可以显示：

```text
结构化数据提取成功；AI 数据检查未完成。
```

而不是清空已经成功的 Extraction 结果。

## 10. MVP 实施顺序

### 小步骤 1：结构和 Mock

新增 Validation schemas、Prompt、抽象 Provider、Mock Provider 和 service。

验收：无网络测试通过，原 ExperimentResult 不变。

### 小步骤 2：Doubao Validation Provider

接入纯文本 API 调用、timeout、诊断、一次 JSON 重试和结构转换。

验收：模拟错误分类通过；使用一份小型结构化数据完成真实调用。

### 小步骤 3：小样本验证

使用 3 份来自真实 Extraction 的脱敏结构化结果测试，不修改 UI。

记录：

- JSON 成功率；
- 平均耗时；
- 输出长度；
- finding 数量；
- 可定位比例；
- 人工判断的正确建议与误报。

完成这些测试后，再决定是否进入 Step 2 人工确认页面增强。

## 11. MVP 验收清单

- [ ] Validation 有独立 Prompt 和 Provider 接口。
- [ ] 不修改 `VisionProvider`。
- [ ] 不修改 `ExperimentResult`。
- [ ] 不调用时不会增加 Extraction 延迟或费用。
- [ ] Validation 只读取观察数据。
- [ ] 输出只包含 warnings、suggestions 和 uncertain_items。
- [ ] 每个可操作 finding 有稳定行列定位。
- [ ] AI 建议不会写入最终数据。
- [ ] API Key 不进入 Prompt、日志或异常详情。
- [ ] timeout 和 JSON 失败不破坏 Extraction 结果。
- [ ] Mock 测试覆盖正常、异常、缺失、定位失败和 timeout。
- [ ] 真实 API 只使用小型脱敏数据测试。
- [ ] 不修改 UI 和 Excel。

## 12. 结论

Validation Step 1 最小方案应采用“独立输入、独立 Provider、独立结果”的设计，不修改 `ExperimentResult`，也不接入现有页面。

最先实现的应是：

```text
validation_schemas
→ validation_prompt
→ MockValidationProvider
→ validation_service
→ 无副作用测试
```

确认结构可靠后，再接入 Doubao Validation Provider。这样可以用最小改动验证第二阶段的价值，同时保证 v0.2.1 Extraction、人工确认和 Excel 导出完全不受影响。
