# v0.2.1.2 Extraction 工程集成报告

## 1. 本次目标

本次将已经验证的 Extraction 模式接入默认 AI 图片识别流程，并为豆包 API 请求增加正式超时保护。旧版 legacy 模式继续保留，可通过显式传入 `stage="legacy"` 使用。

本次没有实现 Validation 阶段，也没有修改 UI 布局、Excel 结构、数据模型或 README。

## 2. 实现内容

### 默认流程

- `DoubaoProvider.process_images()` 的默认阶段由 `legacy` 改为 `extraction`。
- 未显式指定阶段的现有调用现在使用精简 Extraction Prompt。
- Extraction 只返回实验观察数据，不生成 AI 校验建议。

### legacy 回退

- 保留 `stage="legacy"`。
- 显式使用 legacy 时，仍执行原有科研识别 Prompt 和原有后续流程。
- 大图四栏局部编号—数值模式继续优先使用其专用 Prompt，不受默认阶段切换影响。

### API 超时保护

- 单次豆包 API 请求最大等待时间：180 秒。
- 关闭 OpenAI 兼容客户端的隐式自动重试，避免底层重试导致单次请求等待时间不可控。
- 保留项目已有的 JSON 解析失败最多自动重试 1 次机制。
- 对超时异常单独分类为“请求超时”，错误信息会提示可能原因和重试建议。
- 错误信息不包含 API Key。

说明：180 秒限制针对每一次 API 请求。若模型返回了内容但 JSON 解析失败，项目现有的一次显式重试仍可能再发起一次最多 180 秒的请求。

## 4. 结论

v0.2.1.2 默认识别流程已经切换到 Extraction。普通图片和历史截断图片均返回完整 JSON，历史截断样本本次没有再次出现 `finish_reason=length`。

legacy 模式仍可显式调用；大图局部识别流程保持原有专用模式。模拟超时能够被单独识别并转换为用户可理解的中文错误信息。

本次只验证了阶段1 Extraction，没有实现或接入阶段2 Validation。
