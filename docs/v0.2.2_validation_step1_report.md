# v0.2.2 Validation Step 1 实施报告

## 1. 本次范围

本次实现独立的 Validation 基础流程：

```text
ExperimentResult（Extraction 结果）
        ↓
精简、只读 Validation Prompt
        ↓
ValidationProvider
        ↓
ValidationResult
```

Validation 只有被显式调用时才运行。现有图片 Extraction、人工确认、Excel 和 Streamlit 页面均未接入或修改。

## 2. 新增模块

### 数据结构

- `core/validation_schemas.py`
  - `ValidationFinding`
  - `ValidationResult`

`ValidationResult` 包含：

- `warnings`
- `suggestions`
- `uncertain_items`
- `provider`
- `status`
- `response_metadata`

本次没有修改 `ExperimentResult`。ValidationResult 作为独立返回值存在。

### 平台无关服务

- `core/validation_service.py`
  - 提供 `validate_experiment_result()`；
  - 调用前后比较受保护数据，防止 Provider 修改 Extraction 结果；
  - 校验 finding 的行列定位；
  - 无效定位降级为 warning；
  - 单元格 finding 的 observed_value 强制以 Extraction 观察值为准。

### Prompt

- `prompts/validation_prompt.py`
  - 只发送字段、观察行、重复元数据和可选实验背景；
  - 不发送图片、raw_text、模型日志、AI 建议、最终值或 API 配置；
  - 不要求模型返回完整数据表；
  - 只返回 warnings、suggestions 和 uncertain_items；
  - 禁止修改、删除、合并、补写或排序观察数据；
  - 禁止根据规律填补缺失测量值。

### Provider

- `providers/base_validation_provider.py`
  - 新增独立 `ValidationProvider` 抽象接口；
  - 不修改 `VisionProvider`。
- `providers/mock_validation_provider.py`
  - 本地检查空值和模糊字符；
  - 不联网、不产生费用、不推测测量值。
- `providers/doubao_validation_provider.py`
  - 读取现有统一 AI 配置；
  - 执行纯文本 Validation 请求；
  - 严格解析 JSON；
  - JSON 失败最多重试一次；
  - 单次请求 timeout 为 180 秒；
  - SDK 隐式重试关闭；
  - 区分 timeout、网络和 API 错误；
  - 响应诊断不包含 API Key。
- `providers/validation_provider_factory.py`
  - 支持创建 `mock` 和 `doubao` Validation Provider。

## 7. 当前限制

- Validation 尚未接入 Streamlit 页面；
- ValidationResult 尚未写入 ExperimentResult；
- Validation 结果尚未进入人工接受/拒绝流程；
- Excel 尚未记录 Validation 建议；
- 本次未调用真实 Doubao API，只验证了离线请求协议、JSON 解析和错误处理；
- Step 1 只检查结构化数据，不能判断图片是否漏行或复核图片原字符；
- 尚未实现大数据分块 Validation。

## 8. 下一步建议

下一小步应只做 Doubao Validation 小样本验证：使用 1～3 份脱敏的 Extraction 结构化结果，记录 JSON 成功率、耗时、输出长度、finding 定位率和人工判断的建议质量。

真实测试稳定后，再进入 Step 2，把 ValidationResult 接入人工确认页面。AI 建议仍必须由用户明确接受，不能自动覆盖原始值。
