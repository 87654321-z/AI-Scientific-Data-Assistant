# v0.2.2.3 Step 2 Finding Quality Filter 实施报告

## 1. 实施目标

本步骤新增独立的 Validation Finding Quality Filter，用确定性的本地规则为用户生成展示结果。

过滤器只读取 `ValidationResult`，不会修改 Extraction、`ExperimentResult` 或原始 ValidationResult，也不会自动采用任何 AI 建议。

## 2. 新增模块

### `core/validation_quality.py`

公开入口：

```python
build_validation_display_result(
    validation_result,
    medium_limit=8,
    low_limit=4,
) -> ValidationDisplayResult
```

输入是 Provider 和 Validation Service 已经生成的 `ValidationResult`。输出是独立的展示结果，不回写输入对象。

## 3. 展示结果结构

`ValidationDisplayResult` 包含：

- `warnings`：去除重复文本后的 warning；
- `suggestions`：保留用于展示的 AI 建议；
- `uncertain_items`：保留用于展示的不确定项；
- `suppressed_findings`：去重或数量限制后未进入主列表的 finding；
- `summary`：原始数量、展示数量、重复数量、限制数量和无法定位数量。

`SuppressedFinding` 保存：

- finding 的完整副本；
- 原始分类：suggestion 或 uncertain_item；
- 抑制原因：duplicate、medium_limit 或 low_limit。

因此过滤只改变主展示范围，不删除原始信息。

## 4. 实现规则

### 4.1 字段归一化

- 非法 severity 回退为 `medium`；
- 非法 confidence 回退为 `low`；
- 非法 location_status 回退为 `unvalidated`；
- global scope 标记为 `global`；
- cell、row 或 column scope 缺少必要定位字段时标记为 `unresolved`。

本步骤没有读取 ExperimentResult，因此只检查定位字段是否存在，不验证行号是否越界或字段名是否真实存在。完整绑定校验留给后续定位层。

### 4.2 去重

cell scope 使用：

```text
issue_type + row_index + column_name + observed_value
```

其他 scope 使用：

```text
scope + issue_type + column_name + reason
```

去重前先按质量优先级排序，因此重复项中优先保留 severity 更高、定位更明确、confidence 更高的 finding。

### 4.3 排序

排序顺序：

1. severity：high、medium、low；
2. location_status：resolved、recovered、global、unvalidated、ambiguous、unresolved；
3. confidence：high、medium、low；
4. row_index；
5. column_name；
6. finding_id。

### 4.4 数量限制

- high：全部保留，不受限制；
- medium：默认最多 8 条；
- low：默认最多 4 条；
- 数量限制可以通过函数参数调整；
- 超出限制的 finding 进入 `suppressed_findings`；
- 负数限制会得到清晰的 `ValueError`。

### 4.5 原始数据保护

过滤器先深拷贝每个 finding，所有归一化、标记、排序均作用于副本。

不会修改：

- 输入 ValidationResult；
- 原始 suggestions；
- 原始 uncertain_items；
- ValidationRunLog；
- Extraction 或 ExperimentResult。

## 8. 当前使用方式与限制

Quality Filter 当前是独立后端能力，尚未接入 UI：

```python
display_result = build_validation_display_result(validation_result)
```

当前限制：

- 没有 ExperimentResult 输入，因此不能验证 row_index 是否越界；
- 不能验证 column_name 是否属于真实字段；
- 不会通过 row_key 恢复定位；
- severity 只做枚举归一化，不根据科研字段角色重新判断；
- 被抑制 finding 保存在返回对象中，尚未写入运行日志；
- UI 尚未显示数量摘要或 suppressed findings。

下一步应先增加独立的行列绑定校验，再决定是否让现有 Validation UI 使用本过滤器。
