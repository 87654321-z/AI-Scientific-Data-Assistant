# v0.2.2.3 Step 3 Validation Quality UI Integration 报告

## 1. 实施目标

本步骤将独立 Finding Quality Filter 接入现有 Validation UI。

Session State 仍保存 Provider 返回的原始 `ValidationResult`。页面渲染时才创建深拷贝的 `ValidationDisplayResult`，因此排序、去重、定位标记和数量限制不会修改原始结果。

Extraction、`ExperimentResult`、Excel 和 Validation 调用流程保持不变。

## 2. 修改文件

### `utils/validation_ui.py`

新增 UI 数据入口：

```python
build_validation_ui_data(validation_result)
```

该函数调用：

```python
build_validation_display_result(validation_result)
```

只生成展示副本，不覆盖 Session State 中的原始结果。

Validation 结果展示调整为：

- 高风险发现；
- 中风险发现；
- 低风险发现折叠区域；
- 全局 warning；
- 原始 finding、当前展示、重复项、折叠/限制数量统计；
- suppressed findings 数量说明。

每条 finding 的中文表格增加：

- 类别：AI 建议或不确定项；
- 定位状态：已定位、已恢复定位、全局、位置不明确、无法定位或尚未验证。

### `tests/test_validation_ui_state.py`

新增 Quality Filter 接入测试：

- 构造重复的 suggestion 和 uncertain item；
- 验证 UI 数据经过 Quality Filter 去重；
- 验证 high finding 被保留；
- 验证原始 ValidationResult 完全不变。

原有成功、失败降级和 Extraction 隔离测试继续保留。

## 3. 页面统计定义

| 页面指标 | 含义 |
|---|---|
| 原始发现 | 原始 suggestions 与 uncertain_items 总数 |
| 当前展示 | 去重和数量限制后的 findings 数量 |
| 重复项 | 被识别为重复但仍在 suppressed_findings 保存的数量 |
| 折叠/限制 | 当前低风险展示数量加上因数量限制未进入主列表的数量 |

如果存在 suppressed findings，页面会明确说明它们因重复或数量限制未进入主列表，但原始 ValidationResult 仍然完整保存。

## 4. 展示优先级

Quality Filter 使用以下顺序：

1. severity：high、medium、low；
2. location_status；
3. confidence；
4. row_index；
5. column_name。

页面行为：

- high findings 全部展示；
- medium findings 按默认上限展示；
- low findings 放在折叠区域；
- 重复和超限 findings 不进入主表，但完整保存在 Quality Filter 输出中；
- warning 文本在展示副本中去重。

## 5. 原始结果保护

数据流为：

```text
Validation Provider
        ↓
原始 ValidationResult
        ↓ 保存到 Session State
build_validation_ui_data
        ↓ 深拷贝并过滤
ValidationDisplayResult
        ↓
页面展示
```

不会发生：

- 修改原始 suggestions；
- 修改原始 uncertain_items；
- 删除原始 finding；
- 写回 Extraction；
- 将 AI 建议写入最终数据。

## 8. 当前限制

- 页面不展示 suppressed finding 的逐条详情，只显示数量摘要；
- Quality Filter 尚未结合 ExperimentResult 验证行号越界和字段名；
- severity 仍主要来自 Provider，尚未按科研字段角色本地调整；
- location_status 为 unvalidated 的旧 finding 会继续按“尚未验证”展示；
- Validation 建议仍为只读，不会进入人工确认数据。

下一步建议实现后端定位校验，让 cell finding 的 row_index 和 column_name 与 Extraction 结果进行确定性绑定。
