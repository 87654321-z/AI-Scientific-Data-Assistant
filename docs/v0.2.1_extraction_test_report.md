# v0.2.1 阶段1 Extraction 实现与测试报告

## 一、本次目标

实现两阶段架构的第一步：

```text
科研实验图片
→ 阶段1 Extraction
→ 结构化实验观察数据
```

本次只实现数据提取，不实现第二阶段AI校验和建议。

## 二、修改内容

### 1. 新增 Extraction Prompt

新增：

`prompts/extraction_prompt.py`

提供：

```python
EXTRACTION_STAGE = "extraction"
build_extraction_prompt(experiment_context=None)
```

该 Prompt 只要求模型返回：

- `columns`
- `observed_rows`
- 每行的 `replicate_group`
- 每行的 `replicate_index`
- 简短 `warnings`

明确禁止返回：

- `uncertain_items`
- `confidence`
- `basis`
- `suggested_value`
- `suggested_unit`
- `final_unit`
- `content`
- `reason`
- `raw_text`
- 推理过程或长篇解释

### 2. DoubaoProvider 增加阶段参数

`DoubaoProvider.process_images()` 新增一个向后兼容的关键字参数：

```python
stage="legacy"
```

调用方式：

```python
# 旧流程，行为保持不变
provider.process_images(images)

# v0.2.1阶段1
provider.process_images(images, stage="extraction")
```

当前允许：

- `stage="legacy"`：继续使用旧科研 Prompt，并执行已有二次校验。
- `stage="extraction"`：使用新的最小 Extraction Prompt，返回观察数据后立即结束。

其他阶段会给出明确错误。目前尚未实现 `stage="validation"`。

### 3. VisionProvider接口

抽象接口 `VisionProvider.process_images()` 没有修改。

现有调用：

```python
process_images(images, experiment_context)
```

继续有效。

新增的 `stage` 是 `DoubaoProvider` 的可选关键字参数，不影响：

- Provider工厂；
- 当前Streamlit页面；
- MockProvider；
- 旧调用代码。

### 4. 数据结构

没有修改 `ExperimentResult`、`DataRow`、`ColumnInfo` 或 `UncertainItem`。

Extraction返回值继续转换为现有结构：

- 图片直接观察值同时写入 `DataRow.observed_values`；
- 初始可编辑值写入 `DataRow.values`；
- 字段来源标记为 `original`；
- `replicate_group` 和 `replicate_index` 按现有字段保存；
- `uncertain_items` 初始为空；
- AI不自动修改实验数据。

## 五、测试结果

### 5.1 普通图片对照

| 指标 | 旧模式首轮 | Extraction |
|---|---:|---:|
| JSON解析 | 成功 | 成功 |
| finish_reason | `stop` | `stop` |
| 数据行数 | 12 | 12 |
| 输出长度 | 2,945字符 | 2,753字符 |
| Prompt tokens | 4,169 | 1,842 |
| Completion tokens | 4,937 | 4,226 |
| Total tokens | 9,106 | 6,068 |
| API耗时 | 51.380秒 | 46.253秒 |
| 自动重试 | 否 | 否 |

结果：

- 数据行数保持12行；
- 输出长度减少约6.5%；
- total tokens减少约33.4%；
- 本次API耗时减少约10.0%；
- 普通图片没有因为最小Prompt而丢失数据行。

单次API存在随机波动，上述速度变化只能作为本次样本结果，不能直接视为长期稳定提升。

### 5.2 历史截断图片

| 指标 | 旧模式首次响应 | Extraction |
|---|---:|---:|
| JSON解析 | 失败 | 成功 |
| finish_reason | `length` | `stop` |
| 数据行数 | 无法形成结果 | 28 |
| 输出长度 | 8,980字符后截断 | 7,710字符且完整 |
| Prompt tokens | 4,169 | 1,842 |
| Completion tokens | 8,859 | 8,414 |
| Total tokens | 13,028 | 10,256 |
| API耗时 | 91.399秒 | 76.537秒 |
| 自动重试 | 后续重试仍失败 | 不需要重试 |

结果：

- `finish_reason` 从 `length` 变为 `stop`；
- JSON成功闭合；
- 成功生成28条结构化观察行；
- 本次无需自动重试；
- total tokens减少约21.3%；
- 本次API耗时减少约16.3%。

### 5.3 两张图片的小样本成功率

| 模式 | 成功 |
|---|---:|
| 旧模式 | 1/2（50%） |
| Extraction | 2/2（100%） |

这里的2张图片是定向小样本，不代表完整10张benchmark的新成功率。

## 六、是否解决JSON截断

对本次测试的历史失败图片，**已经解决**：

- 旧模式：`finish_reason=length`
- Extraction：`finish_reason=stop`
- 旧模式：JSON不完整
- Extraction：JSON完整
- 旧模式：无法产生 `ExperimentResult`
- Extraction：返回28行

这再次验证：

> 把详细不确定项、建议、依据和置信度从首轮移走，可以显著降低首轮JSON截断风险。

但目前只测试了一张历史截断图片。正式启用前仍需对原10张图片完整回归。

4. 第二阶段 `validation` 尚未实现。
5. Extraction只保留模糊字符或简短warning，不生成AI建议。
